# 2026-06-05 세션 요약

## 📌 주요 진행 사항
1. **10단계 테스트 계획 완수 (Step 2 ~ Step 10)**
   - `libhmalloc` 환경변수 엣지 케이스 파싱 및 단일 스레드 안전성 확보
   - C ABI FFI 경계 예외 테스트 (`hfree(NULL)`, `hmalloc(0)`, `hmalloc(usize::MAX)`, `hposix_memalign` 제약) 완료
   - 멀티스레드 동시 할당/해제 스트레스 테스트 및 대규모 메모리 사이클 검증 성공
   - Jemalloc extent hook 및 NUMA `mbind` 정책 강제 주입 통합 검증

2. **발견 및 해결된 크리티컬 버그**
   - **C11 / POSIX Alignment 위반 수정**: 기존 `hposix_memalign`에서 void 포인터 배수 여부를 검사하지 않던 점과, `haligned_alloc`에서 size가 alignment의 배수여야 하는 C11 제약 조건 추가.
   - **Jemalloc Bootstrap EAGAIN (에러코드 11) 버그 해결**: `mallctl("arenas.create")` 호출 시점 이전에 Jemalloc 백엔드가 아직 부트스트랩 되지 않았을 경우 발생하던 `EAGAIN` 에러를, Dummy `je::mallocx(1, 0)` 할당/해제를 통해 강제 초기화 하도록 하여 해결.
   - **hmctl 바이너리 LD_PRELOAD 누락 수정**: `setup_environ()` 함수에서 라이브러리 경로를 `LD_PRELOAD` 환경 변수에 주입하는 로직을 추가하여 `ls` 커맨드와 같은 바이너리를 `hmctl`로 안전하게 후킹 실행할 수 있도록 통합.
   - **Valgrind 누수 점검**: `libhmalloc`에 대한 메모리 누수 및 Undefined Behavior를 점검하였으며, 메모리 누수 없음(Definitely lost: 0 bytes)을 완벽히 증명.

## 📝 교훈 (Lessons Learned)
- `tikv-jemalloc-sys`의 `mallctl`을 호출할 때 런타임에 초기화가 안 되어 있으면 `EAGAIN` 에러가 날 수 있으므로, 초기화 부트스트랩을 명시적으로 트리거하는 것이 중요하다.
- Rust에서 C FFI 기반 API를 구현할 때, POSIX나 C11 표준에서 요구하는 예외 케이스(예: 2의 거듭제곱, 포인터 크기 배수) 제약을 빼먹지 않도록 꼼꼼히 확인해야 한다.
- Valgrind 검사 시, Rust 내부의 쓰레드 로컬 스토리지 초기화에 의한 1회성 할당(Possibly lost)이 발생할 수 있으며, 이는 allocator 자체의 결함은 아니다.
